# ★ 핵심 주의사항 (실작업에서 얻은 교훈, 2026-05 마사회 진위조회 작업 기준)

[1] 정부24 문서확인번호(passNum) 자릿수
- 형식은 4-4-4-(4 또는 5). 진위확인 폼이 박스 4칸이라 하이픈으로 나눈 그룹이 '정확히 4개'여야 한다. (server verifyService.js는 passNum.split("-").length===4 만 확인, 자릿수는 미검사)
- 마지막 그룹만 5자리가 될 수 있다. 절대 4-4-4-4로 강제하지 말 것.
- 반대로 '중간 그룹'이 5자리로 읽히면 거의 100% OCR 오류다(인접 그룹 숫자 병합/중복). 이 경우만 교정한다.
- 마지막 그룹이 5자리로 '일관되게' 읽히면 그대로 보존(예: 0036처럼 앞자리 0 포함 가능).

[2] OCR 추출 전략 (정규식만으로는 부정확 → LLM/직접 판독 병행)
- 1차 CLOVA OCR 후, 숫자가 흔들리는 문서확인번호는 fitz로 '상단 문서확인번호 영역만' 좁게 crop + zoom 6~8배로 재OCR하면 깨끗하게 읽힌다.
- 같은 영역을 2~3회(다른 zoom/밴드) 재OCR해 다수결로 확정하면 신뢰도가 높다.
- 정규식 단독 파싱은 5자리 오인식·마스킹(******)·테이블 레이아웃에서 자주 틀림. 원문을 직접 읽고 판단할 것.

[3] CLOVA OCR 이미지 해상도 한도
- jpg/png(특히 카메라 촬영본)는 dpi 그대로 보내면 'The image resolution limit has been exceeded' 에러. 최장변 ~2200px로 다운스케일 후 전송.
- PDF는 dpi 200 정도면 무난. 통합 PDF(한 파일에 여러 서류)는 페이지별로 OCR해 대상 서류 페이지를 찾을 것(파일명만 믿지 말 것 — 동의서의 '신체장애' 같은 단어에 오매칭 가능).

[4] 장애 관련 서류 구분 (헷갈림 주의)
- '장애인증명서'(보건복지부, 장애인복지법 시행규칙 별지 제9호서식) = 정부24 문서확인번호 있음 → govDisabilityVerify.
- '중증장애인 확인서'(한국장애인고용공단, 장애인고용촉진법 별지 제2호서식) = 별개 서류. 정부24 문서확인번호가 있는 출력본도 있고(→진위확인 가능), 없는 출력본(고용공단 직접 발급)도 있음(→정부24로는 진위확인 불가).
- 주민번호가 마스킹(******)돼 birth(주민앞6)를 못 뽑으면 장애인증명서 input의 birth 필수조건을 못 채우므로 제외/수기처리 대상.

[5] 수급자증명서(기초) 출력본 종류 & 2차 입력
- 정부24 출력본: 상단에 '문서확인번호 ... 정부24 ... gov.kr ... 인터넷발급문서진위확인' → 진위확인 가능.
- 보건복지부/복지로 출력본([서식11호] 류): 문서확인번호 없음 → 정부24 진위확인 불가, 제외/수기처리.
- ★ 2차 입력이 성명 또는 발급번호로 '랜덤'이다(장애인증명서와 동일 패턴). 성명만 넣는 govVerify로 처리하면 발급번호 요청 케이스에서 전부 '처리중 오류'(result 0)로 실패한다.
  → verifyService.js에서 수급(includes("수급"))은 govDisabilityVerify로 라우팅. input에 발급번호(extraNum) 필수.
  실제 사례(2026-05 마사회): 성명 분기 6명 성공 / 발급번호 분기 9명이 govVerify로 실패 → 발급번호 채워 재시도.

[6] 정부24 진위확인 90일 만료
- 정부24 인터넷발급문서 진위확인은 '발급일로부터 90일까지'만 가능. 발급일이 90일을 넘으면 문서확인번호가 맞아도 '문서 없음'(result 0)으로 뜬다.
- 이 경우 OCR/번호 문제가 아니라 만료이므로 재추출로 해결 불가 → 재발급 요청/수기처리. (사례: 장애인증명서 발급일 2025/12, 2026/01, 2023/07 건들이 '문서 없음')
